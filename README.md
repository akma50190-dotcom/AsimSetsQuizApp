# 🇱🇾 ليبيا إكسچنج PRO — Production 4.0

منصة ويب عربية لمتابعة أسعار الصرف في ليبيا، مبنية على Node.js/Express مع PostgreSQL كتخزين دائم للإنتاج.

## ما الجديد في 4.0؟
- PostgreSQL هو مخزن البيانات الأساسي في الإنتاج.
- جداول منفصلة للأسعار الموازية، أسعار المصارف، التاريخ، التنبيهات، الإعدادات والمستخدم الإداري.
- فهرس زمني للتاريخ لتسريع الرسوم والاستعلامات.
- Connection Pool عبر `pg`.
- دعم TLS لقاعدة البيانات.
- `render.yaml` ينشئ Web Service + PostgreSQL ويربط `DATABASE_URL` تلقائيًا.
- سكربت `migrate-json.js` لترحيل `data/db.json` القديم إلى PostgreSQL.
- `/health` لمراقبة صحة الخدمة.
- حفظ تاريخ الأسعار بشكل دائم بدل الاعتماد على نظام ملفات الاستضافة.

## التشغيل المحلي بدون PostgreSQL
يمكن تشغيل المشروع محليًا بدون `DATABASE_URL`، وسيستخدم `data/db.json` للتجربة فقط.

```bash
npm install
npm start
```

الموقع: `http://localhost:3000`
الصحة: `http://localhost:3000/health`
الإدارة: `http://localhost:3000/admin.html`

## تشغيل PostgreSQL محليًا
ضع `DATABASE_URL` في البيئة، ثم:

```bash
npm install
npm start
```

سيتم إنشاء الجداول تلقائيًا عند بدء الخادم.

## ترحيل البيانات القديمة
إذا كان لديك `data/db.json` يحتوي على بيانات مهمة:

```bash
npm install
node migrate-json.js
```

ثم شغّل الموقع باستخدام نفس `DATABASE_URL`.

## النشر على Render
الملف `render.yaml` مجهز لإنشاء:
- Web Service: `libya-exchange-pro`
- PostgreSQL: `libya-exchange-db`

ويتم ربط `DATABASE_URL` تلقائيًا بقاعدة البيانات الداخلية. Render توصي باستخدام اتصال قاعدة البيانات الداخلي عندما تكون الخدمة وقاعدة البيانات في نفس المنطقة، لأنه يستخدم الشبكة الخاصة ويقلل زمن الاتصال. citeturn1search1turn1search8

الخطوات:
1. ارفع المشروع إلى GitHub.
2. في Render اختر إنشاء Blueprint من المستودع.
3. Render يقرأ `render.yaml` وينشئ الخدمة وقاعدة PostgreSQL.
4. أدخل `ADMIN_PASSWORD` و`FULUS_API_KEY` عندما يطلبهما Render.
5. `JWT_SECRET` يتم توليده تلقائيًا في Blueprint.
6. بعد نجاح النشر استخدم رابط `onrender.com` الذي تمنحه Render.

## متغيرات الإنتاج
- `DATABASE_URL`: يتم توفيره تلقائيًا بواسطة Render Blueprint.
- `ADMIN_PASSWORD`: كلمة مرور الإدارة، يجب أن تكون قوية.
- `JWT_SECRET`: سر توقيع جلسات الإدارة؛ Blueprint يولده تلقائيًا.
- `FULUS_API_KEY`: مفتاح Fulus إذا أردت التحديث التلقائي للسوق الموازية.
- `REFRESH_MINUTES`: الفاصل الزمني للتحديث، الافتراضي 5 دقائق.
- `PGPOOL_MAX`: الحد الأقصى لاتصالات PostgreSQL من الخدمة.

## الاعتمادية ومصادر البيانات
- السعر الرسمي يُسحب من صفحة أسعار الصرف الرسمية لمصرف ليبيا المركزي.
- السوق الموازية تستخدم Fulus API عند توفير مفتاح API صالح، ولا يتم اختلاق أسعار تلقائية عند غياب المصدر.
- أسعار المصارف الحالية موصولة بالمصرف الوطني التجاري فقط؛ لا يتم اختلاق أسعار لمصارف أخرى.
- كل مصدر يجب أن يحمل مصدرًا ووقت تحديث، والبيانات الموازية ليست سعرًا رسميًا.

## ملاحظة إنتاجية مهمة
PostgreSQL يحل مشكلة فقدان البيانات عند إعادة تشغيل/إعادة نشر الخدمة، لكنه لا يجعل النظام وحده "مضمونًا 100%". للإطلاق التجاري يوصى بتفعيل النسخ الاحتياطية والمراقبة، واستخدام خطط قاعدة بيانات مناسبة لحجم الزيارات، وضبط عدد اتصالات الـpool حسب عدد نسخ الخدمة. node-postgres يحذر من تجاوز حدود اتصالات PostgreSQL عند تشغيل عدة نسخ من الخدمة. citeturn0search10

## الأمان
لا تضع كلمات المرور أو مفاتيح API داخل GitHub. استخدم Environment Variables/Secrets في الاستضافة.
